# 专用服务器形态：命令可用性普查

在真实 `arma3server_x64.exe` 上实测（`server/` 测试环境，BattlEye 关），2026-09-25。

目的：把"无头环境下到底哪些能用"从推断变成事实 —— 它直接决定 UI/输入类工具该
拒绝什么、以及哪些命令需要额外警告。

## C. 静默无效 / 假值 ← **本次普查的主要收获**

| 命令 | 服务器上返回 | 客户端上本来会怎样 |
|---|---|---|
| `hint _p0` | `nil`，**不报错** | 弹出消息 |
| `forceMap _p0`、`openMap _p0` | `nil`，**不报错** | 打开地图 |
| `systemChat _p0` | `nil`，**不报错** | 显示聊天 |
| **`getPos player`** | **`[0,0,0]`** | 玩家的真实位置 |
| `side player` | `"SIDE"`（不是 `WEST`/`EAST`） | 真实阵营 |
| `name player` | `"Error: No vehicle"` | 玩家名 |
| `count allMissionObjects _p0` | `nil`（不是数字） | 实体数 |
| `count allDisplays` | `0` | display 数 |
| `isNull player` | **`true`** | `false` |

共同特征：**不报错**，返回 `nil` 或**看起来合理的假值**。

`getPos player → [0,0,0]` 尤其危险 —— 调用方完全可能把它当成"玩家在原点"而不是
"这个环境没有玩家"。这与本项目一直在打击的失败模式同源（见 `decisions.md` 的
D21/D23：症状是"没反应"或"结果不对"，而没有任何错误信息）。

## D. 一个意外：动态表达式里的 config 路径操作失效

```
isClass (configFile >> "CfgVehicles" >> "All")                              → nil
getText (configFile >> "CfgVehicles" >> "B_MRAP_01_F" >> "displayName")     → nil
```

**而工具层的 config 查询是正常的**（同一个 `B_MRAP_01_F`，`config_class` 能读出
17 项属性）。两者走的是不同路径：

- 工具层 → 模组的 `a3mcp_fnc_configQuery`（SQF 函数，可用）；
- 动态表达式 → 经 `exec` 的表达式求值（返回 nil）。

**原因未查明**。可能是服务器环境下 `configFile` 的表现不同，也可能是表达式求值
路径上的其它环节 —— 我没有证据，所以只记现象。要留意的是：**这会让"用 `exec`
直接读 config"这条路在服务器上静默失败**，而工具层的 `config_*` 不受影响。

## 对工具层的启示

两个**可用的运行时探针**：

- `isNull player` → 服务器上为 `true`：直接回答"有没有玩家"
- `count allDisplays` → 服务器上为 `0`：直接回答"有没有界面"

它们比"进程名 / 找不到窗口"更贴近能力边界的**本质**。将来若要把 C 类命令做成
执行后警告（而不是等调用方自己发现结果是假的），这两个就是判据。

## C 类警告：实测验证（2026-09-25）

`exec` 现在会在命中清单时附注警告。在专用服务器上实测四个表达式，两个该警告、
两个不该，结果都对：

| 表达式 | 结果 | 警告 |
|---|---|---|
| `hint _p0` | `nil` | ✅ 有 —— 说明"返回 nil 且不报错、屏幕上不会有任何东西" |
| `getPos player` | `[0,0,0]` | ✅ 有 —— 说明是假值而非报错，不要当真实数据 |
| `worldName` | `"Altis"` | ✅ 无 |
| **`count allUnits`** | **`0`** | ✅ **无** |

最后一条是这个判据的**关键对照**：它返回 0，但那个 0 是**真实值**（空场景），
所以不该警告。判据因此是按"**是否依赖玩家／是否 locale effect**"定的，而不是
"结果看起来可疑就警告" —— 后者会把大量正常结果误标，而误报会让调用方开始忽略
全部警告，比没有警告更糟。
