# 来源与移植说明（provenance）

本仓库**不依赖**本机任何其它 Arma 代码库：不 import、不 subprocess 调用、数据自带、
部署自带。这条约束由 `tools/check_independence.py` 作为可执行断言守护。

但"不依赖"不等于"闭门造车"。下面逐条记录：**从哪些既有工程经验里学到的结论**，
以及为什么那条结论可信。代码是重新写的，结论是有出处的。

---

## 从 arma_llm_commander（ALC）移植的结论

该工程实现了"游戏进程内扩展 DLL + SQF 网关 + 桥接进程"的完整链路，是本机验证过
最充分的运行时通道。以下结论直接影响本项目的设计：

| 结论 | 为什么可信 | 本仓库如何体现 |
|---|---|---|
| 游戏进程**无法被外部主动推送**，只能由 SQF 主动轮询 `callExtension` 取命令 | 引擎不提供回调机制；该工程实现了游戏主动 poll 模型并长期使用 | `adapters/channel.py` 的通道接口按"请求-回执"设计，不承诺服务端推送 |
| 导出函数在游戏逻辑线程内执行，**内部绝不能阻塞** | 引擎侧注释明确记录；阻塞会卡住游戏帧 | P1 的 DLL 设计中网络/IO 一律交给后台线程（写入 `docs/deploy.md`） |
| 单条命令的错误**可能杀死整个主循环**，导致系统彻底失联 | 该工程记录过一次上机事故：坏参数抛出运行时错误后 RPT 再无输出 | P0 已落实为：`mcpcore` 保证工具异常不杀死服务器（24 个协议用例覆盖）；P1 的 SQF 执行器需按此设计 |
| 下行队列有容量上限，**满时丢弃最老的命令且无任何回报** | 该工程扩展的实现如此，并在文档中记录了后果 | `exec_batch` 默认上限 8 条，超限**拒绝**而非截断（见 D11） |
| 命令关联 id 的前缀（`@<cid>:`）在多处被遗漏，导致回执"看不见" | 该工程的错误记录里同类问题复发多次 | 本仓库只在序列化/通道层处理 cid，且要求所有回执原样带上（P1 落实） |
| `sideChat` 是 locale effect：在专用服务器上执行，玩家阵营频道收不到 | 该工程实机踩过并记录了修复方式（改为 remoteExec 到客户端执行） | 能力矩阵把 UI 类操作标注为"必须在有玩家的进程内执行" |
| LLM 拿不到画面，只能靠接口获取信息；地形/单位描述必须结构化 | 该工程的核心前提，且已有配套的地形栅格工程 | 所有工具返回值都是自解释文本 + 结构化字段 |

## 从 arma3-sqf-skill 移植的结论

| 结论 | 为什么可信 | 本仓库如何体现 |
|---|---|---|
| SQF 命令名或参数写错**通常不报错**，只在运行时静默失败 | 该技能的核心纪律，来自反复的实际排查 | `exec` 前置查库 + 参数校验 + `dry_run`；未知命令明确拒绝并给相近建议 |
| 命令签名应以离线命令库为准，不凭记忆写 | 该技能建立了 5181 条离线命令库并据此工作 | 本仓库以同一来源（编辑器扩展的官方定义）自建数据副本，且**保留了 compatibility 字段** |
| 静态检查 ≠ 引擎验证 | 该技能的交付纪律明确区分二者 | 本项目同样区分"本机可验证"与"需上机验证"，见 `README.md` 状态表 |

**注意**：本仓库的数据来源是**编辑器扩展**（SQFLint）自带的官方命令定义，
而不是该技能的派生索引。两者同源，但本仓库直接取原始来源，因此获得了
`compatibility`（版本兼容）字段——该技能的派生索引在精简时裁掉了它。

## 从 arma3-terrain-grid 移植的结论

| 结论 | 为什么可信 | 本仓库如何体现 |
|---|---|---|
| `diag_log` 是零依赖、容量无上限的上行通道（引擎没有通用文件写入命令） | 该工程用 `TGRID\|v1\|` 前缀分片协议实测跑通了整张地图采样 | P1 的上行通道设计依据；`diag_log` 在本仓库被列为 EXOTIC 级（不设闸门会污染事件流） |
| 单机/服务器形态下启动参数可指定 `-profiles`，RPT 落在该目录 | 该工程的部署手册记录了完整可执行的启动方式 | P1 的部署与日志定位依据 |
| `.bat` 必须纯 ASCII + CRLF，否则 cmd 按 ANSI 读会乱码并破坏解析 | 该工程记录了踩坑与脚本化修复 | P1 部署脚本按此约束编写 |

## 引擎能力矩阵的核查方式

`data/capabilities.json` 里的每一条结论（如"引擎无法注入鼠标点击"）都：
1. 通过对自带命令库的**穷举检索**得出（不是抽样，不是凭记忆）；
2. 由 `tools/build_capabilities.py` **逐条核对**其依据命令确实存在、版本一致；
3. 声明"引擎内做不到"的条目，其 `commands` 为空——空虚的依据也是一种证据。

核对不通过则拒绝生成数据文件，因此文档与数据不会漂移。
